## A. What I decided before prompting (Task 1 design)

| Item | Decision |
|---|---|
| State | `(row, col)` tuple |
| Warehouse | list of strings parsed from the ASCII map; S and G located once at parse time |
| Valid actions | Up/Down/Left/Right; invalid if outside the map or the target cell is `#` |
| Goal test | `state == goal`, checked when a state is removed from the frontier |
| Frontier | binary heap of `(f, h, counter, g, state)`; ties: lowest f, then lowest h, then oldest |
| Repeated states | dict `best_g`; push a state again only if the new g is strictly smaller |
| Path | `parent` dict, walked backwards from G and reversed |
| Reported | found?, path, length (moves), states expanded (also unique expanded and generated) |
| Counting rule | "expanded" = every non-stale state removed from the frontier, the goal included |

## B. Predictions written before running anything

1. A* with Manhattan finds a path of 40 moves (I traced the map by hand: 16 moves to reach
   the cell above the bottom corridor, then 24 more along the top).
2. BFS also finds 40 moves. A* expands fewer or equal states, but not by much, because the
   map is a winding corridor and Manhattan distance points the wrong way for long stretches.
3. h = 0: still 40, and the expansion count is close to BFS.
4. Euclidean: still 40 (it is admissible), expansions >= Manhattan.
5. 2 x Manhattan: fewer expansions than Manhattan; the path might stop being optimal.
6. The five deliberately broken A* versions in `src/broken_astar.py` are all caught by the tests.

## C. Prompts used with the LLM

**Prompt 1 (Task 2, code generation)** - based on the lab's example prompt plus my design:

```text
I am implementing a simple goal-based search agent in Python. The environment is a
grid represented by an ASCII map. The agent starts at S and must reach G. '#' is an
obstacle and '.' is a free cell. The agent can move up, down, left or right and every
move costs 1. Implement A* search using Manhattan distance as the heuristic.
Represent states as (row, col) tuples. Use a heapq frontier ordered by (f, h, counter).
Keep a dict of the best g found per state and only push a state again if it is cheaper.
Test the goal when a state is removed from the frontier. Reconstruct the path with a
parent dict. Report whether a path was found, the path, its length and the number of
states expanded. Keep it simple and explain the main components. Use only the
standard library.
```

**Prompt 2 (Task 5, BFS version)**:

```text
Write a BFS version of the same agent for the same grid problem. Use the same
SearchResult and the same counting rule (a state counts as expanded when it is
removed from the queue; the goal test is done at removal).
```

**Prompt 3 (Task 6, heuristic explanation)**:

```text
Why is Manhattan distance an appropriate heuristic when the robot can only move
horizontally and vertically, one cell at a time, with cost 1 per move?
```

Summary of the answer (Claude's, shortened): each move changes either the row or the
column by exactly 1, so at least |dr| + |dc| moves are needed even with no obstacles;
obstacles can only add moves. So h never overestimates (admissible). It is also
consistent, since one move changes h by at most 1 and costs 1.

I did not ask the LLM what happens with h = 0, Euclidean or 2 x Manhattan; those were
answered by running the experiments (REPORT.md, Task 6).
